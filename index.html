Checklist to 100%

1

Write the idea as one sentence

5 min

Without a clear goal, Claude will guess on your behalf. Describe what the product does, who it's for, and what "done" looks like.

  • One sentence: "I want [what] for [who], so that [outcome]"
  • Define the Definition of Done — how you'll know it's finished
2

Install Claude Code locally

10 min · one-time

This is a one-time setup per machine. After this, it's just running claude inside the project folder.

node -v || brew install node
npm install -g @anthropic-ai/claude-code
claude --version
claude   # sign in via browser or set ANTHROPIC_API_KEY
3

Create the project and folder

5 min

A new folder means a new git repository. That way you can deploy at any moment later on.

mkdir my-project && cd my-project
git init
claude
/init   # Claude scans the project and creates a starter CLAUDE.md
You'll need an empty GitHub repository at step 7 — you can create it right now on github.com.
4

Describe the task and ask for a plan

Plan mode

Don't ask Claude to write code right away. Ask for a plan first — one you can correct before anything actually changes.

# Shift+Tab turns on Plan mode
I want to build: [your sentence from step 1].
What's the simplest approach? Create a step-by-step plan
before writing any code.
5

Implement with verification, not by eye

Implement

The golden rule: don't just ask Claude to "do it", ask it to "do it and verify it". Give Claude a test, a build, or a screenshot as the acceptance criteria.

Implement the plan. Run the app/tests after each change
and fix failures before moving on. Show me the result
(screenshot or test output) when done.
6

Check it yourself, with your own eyes

QA · 5 min

Even with automated checks, always open the result yourself. Walk through the key scenarios like a real user would.

  • Opened and tried the main scenario manually
  • No errors in the console / logs
  • Works at mobile screen size, if it's a web app
7

Commit and push to GitHub

Commit

Ask Claude for a meaningful commit message right away — don't leave it for "later".

commit with a descriptive message

# then in the terminal:
git remote add origin https://github.com/USER/REPO.git
git push -u origin main
8

Deploy and check the live link

Deploy

For a static site — GitHub Pages with auto-deploy on every push. The repo should already have a workflow file for this.

# Settings → Pages → Source: GitHub Actions
# Actions → Deploy GitHub Pages → check that the run is green

# open the site:
# https://USER.github.io/REPO/

100%. Deployed 🎉

You've gone from idea to a live link. For a new idea, just reset your progress and start again.

Level up the flow

Once the 8 steps feel natural, these four habits make Claude noticeably more reliable on bigger projects.

Steering

CLAUDE.md

A short root file Claude reads at the start of every session. Only include what Claude can't infer from the code: build/test commands, unusual conventions, repo etiquette, and verification criteria.

## Project
Build: npm run build. Test: npm test.

## Code style
Use ES modules, not CommonJS.

## Workflow
Run tests after changes. No premature abstractions.

Enforcement

Hooks

CLAUDE.md is advice — it's not always followed. Hooks are deterministic scripts that run automatically, guaranteeing an action every single time, like auto-formatting or blocking dangerous commands.

Write a hook that blocks 'git push' directly to main
and suggests opening a PR instead.

Write a hook that runs prettier after every Edit/Write.
Full guide →
Focus

Context management

Response quality drops well before the context window fills up. Keep one task per session, clear between unrelated topics, and dump progress to a file before clearing so nothing important is lost.

Dump current plan and progress to PROGRESS.md.
/clear
Read PROGRESS.md and continue from where we left off.
Full guide →
Scale

Automation

Once the basic loop works, move repeatable tasks to headless mode: no interactive UI, just a prompt in and a result out. Useful for CI, batch migrations, and diff reviews.

claude -p "review the staged diff and list risks" \
  --output-format text
